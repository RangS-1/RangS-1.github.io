Pull Request: memahami ekosistem open source di github

Apa itu Pull Request? Mengapa penting bagi software open source? kita bahas lengkap di artikel ini.

#pull request #github #open source

Apa itu Pull Request?

Pull Request adalah salah satu cara kontribusi untuk repository open source di github.

“Open source is a development methodology; free software is a social movement.”
— Richard Stallman, Open Source Initiative Founder

Pada artikel ini, kita akan bahas tentang Pull Request, terutama pada etika kontribusi terhadap open source.

Pull Request

Jadi apa itu Pull Request? pull request adalah sistem untuk mengajukan usulan atau permintaan resmi untuk menggabungkan kode atau memperbaiki kode pada sebuah project open source.

Bayangkan seperti ini, kita adalah pengguna biasa dan menggunakan aplikasi-aplikasi yang berhubungan dengan open source, contoh paling nyata adalah Visual Studio Code. Kita sedang menggunakan aplikasi tersebut, tetapi kita menemukan bug dari aplikasi tersebut. Karena itu kita membuat versi kita sendiri dan membuat pull request agar orang lain yang menggunakannya tidak lagi mendapatkan bug tersebut pada versi mereka.

Etika Open Source

Dalam project besar yang bersifat open source, terdapat beberapa etika yang perlu diperhatikan. Sejauh yang kutahu, etika project open source biasanya tersimpan dalam file CONTRIBUTING.md dan CODE_OF_CONDUCT.md. Project open source besar biasanya memiliki CONTRIBUTING.md yang berisi cara kerja untuk kontribusi pada mereka. Namun, di sini aku akan menjelaskan cara normal yang biasa digunakan oleh project-project kecil.

Membuat Pull Request

Langkah pertama dalam membuat pull request adalah dengan membuat fork atau aplikasi versi dirimu sendiri. Setelah membuat fork di akun githubmu sendiri, kau bisa cloning dengan perintah git: 

git clone https://github.com/<nama-akunmu>/<nama-project>

Jika sudah selesai cloning, ya waktunya bekerja. Misalnya kau cloning sebuah project web, kau bisa memberi tambahan berupa fitur baru atau perbaikan bug pada project tersebut. Kalau sudah selesai membuat fiturmu sendiri, kau bisa commit dan push ke repositorymu dengan perintah: 

git add .
git commit -m "Fitur Barumu"
git push origin main

Setelah berhasil push ke fork repositorymu, coba buka halaman repository di github, harusnya kau bisa melihat tombol Contribute yang ketika diklik akan ada tombol open pull request. 

wingetcreate submit <path-to-manifest-file>

Tetapi, jika validasi manifest berhasil, biasanya akan ada pertanyaan untuk mengirimkan package ke Winget.

Jika muncul pertanyaan untuk membuat pull request, kau bisa mengetik "y" dan enter, maka ia akan membuat pull request ke Winget dengan cara fork repository winget-pkgs ke akun githubmu. Nanti kau akan diminta untuk login ke github dan diberi link pull request jika validasi berhasil. Oh ya, jika kau sudah pernah mengirimkan package ke Winget, kau harus sync fork repository winget-pkgs terlebih dahulu, karena jika tidak maka kau tidak akan bisa membuat pull request dengan wingetcreate.

Review dari Microsoft Team.

Bisa kau lihat dari gambar di atas, gambar di atas adalah tampilan halaman pull request yang kita buat dengan wingetcreate. Pada pull request tersebut juga terdapat beberapa checklist yang harus dilalui sebelum package kita diterima oleh Winget. seperti: 

winget validate --manifest <path-to-manifest-file>
winget install --manifest <path-to-manifest-file>

Setelah melakukan validasi dan installasi melalui manifest, kita perlu menceklis pada pull request bahwa validasi dan installasi berhasil. Jika semua itu selesai, kita hanya perlu menunggu review dari wingetvalidator-prod dan maintainer asli winget.

Dari pengalamanku, biasanya review dari wingetvalidator-prod akan cepat, tetapi review dari maintainer asli winget bisa memakan waktu hingga beberapa minggu, kalau tidak salah sekitar 2 minggu. Setelah 2 minggu menunggu review dari maintainer asli winget, aku mendapatkan response melalui komentar pull request bahwa ada perbaikan yang perlu dilakukan.

Maintainer asli winget bernama Stephen Gillie, dia yang memberikan komentar perbaikan yang harus kulakukan pada package yang kubuat. Sementara itu, Demitrius Nelon mengecek kembali package yang kubuat, setelah sesuai dan tidak ada error, ia memberikan moderator-approved dan wingetbot otomatis merge pull requestku ke repository winget-pkgs.

Oh ya, aku hampir lupa untuk menceritakan bagaimana cara memperbarui pull request yang sudah dibuat. Sebenarnya caranya cukup simple, pada halaman pull request, kau bisa klik bagian "Files changed" dan klik titik tiga di pojok kanan atas, nanti akan ada pilihan untuk "Edit File". Setelah selesai mengedit file, cukup commit dan tunggu proses review sekitar 2 minggu lagi.

Testing dengan PowerShell/Command Prompt

Setelah package kita diterima oleh Winget, kita bisa menginstall package tersebut melalui terminal. Bisa menggunakan PowerShell atau Command Prompt. Berikut adalah perintah untuk menginstall package yang sudah diterima oleh Winget: 

winget install <package-kamu>

Jika proses install berhasil, artinya selamat! package yang kau buat sudah bisa digunakan oleh semua pengguna Windows 10 dan 11+ dengan perintah winget tersebut. Kamu bisa mengecek package yang kubuat di winget-pkgs repository.

Kesimpulan

Membuat package di Winget merupakan pengalaman yang menarik, karena kita belajar bagaimana ekosistem package manager bekerja di Windows. Meskipun Winget masih dibilang baru, tetapi sudah cukup baik untuk digunakan sehari-hari. Aku berharap Winget bisa menjadi package manager yang lebih baik lagi di masa depan.
